# LectureForge

**把一节原始录课，自动加工成带双语字幕的可发布成片。**

[English](README.md) · [环境搭建](docs/setup.md) · [技术方案](docs/design.md) · [市面方案调研](docs/landscape.md)

---

## 要解决的问题

现成的自动剪辑工具，判据只有一条：**音量低于阈值且持续 N 秒 → 剪掉**。

这条规则对口播短视频是对的，对课堂是灾难性的。老师说「**大家想一想**」然后停四秒——这四秒不是卡壳，是在等学生。剪掉之后课就听不懂了。

我实测过：`auto-editor` 加上 `subtitle:pattern=想一想` 做保护，输出和纯音量阈值**完全一致**。原因是字幕只覆盖「台词所在的那段时间」，覆盖不了「台词之后的沉默」，而教学留白全都发生在台词之后的沉默里。这是范式级缺口，不是调参能解决的。

所以本项目把这件事当作核心问题：把沉默按七个加权信号分类（填充音、相对全片 P95 的停顿时长、语速骤降、虚词结尾、重启重复、意图词、画面活跃度），再决定**剪掉、压缩、还是保护**。

核心原则是**压缩而非删除**：2.4 秒的卡壳压到 0.35 秒。归零会变成机关枪节奏，听三分钟就累。

## 当前状态

说实话：**v0.1，字幕这一半做完了，剪辑那一半没有。**

| 阶段 | 状态 | 说明 |

| 卡壳 / 故意停顿判定 | ⚪ 已设计 | 模型已定，无代码 |

**今天就能做的**：一条命令，把录像变成带双语字幕的成片。自动剪辑在 v0.2。

## 实测数据

基准：72.5 秒合成讲课音频，埋入 13 个专业术语、数字和同音字陷阱，有标准答案可算错误率。

| 阶段 | 字准确率 | 靠什么提上来 |
|---|---|---|
| whisper `medium` / int8 原始输出 | 83.2% | — |
| + 繁 → 简统一 | 94.0% | whisper 会在句中整段切繁体，还会让术语表全部失配 |
| + 术语 / 同音字 / 断句修正 | **97.9%** | 定向修正 + 标点回溯断句 |

转写速度：i5-12450H 上 **1.36x 实时**（纯 CPU，8 线程，int8）。45 分钟的课约 33 分钟。

人工复核量从 37% 降到 **16%**，而且清单直接告诉你**哪个字**可疑，而不是整条标红。

真正的三个瓶颈全是工程问题，不是模型上限：简繁混杂、同音字（拟合→你和）、断句切开词和小数点。三条都在 `subs.py` 里处理掉了。

## 快速开始

```bash
# 1. 装带 libass 的 ffmpeg 到 tools/（见 docs/setup.md）
# 2. 环境
python -m venv .venv && .venv\Scripts\activate
pip install -e .

# 3. 自检
lectureforge doctor

# 4. 只出中文字幕
lectureforge subtitle 录课.mp4 --no-translate

# 5. 出字幕并烧录成片
lectureforge subtitle 录课.mp4 --burn

# 6. 带英文（任意 OpenAI 兼容接口）
set LLM_API_KEY=sk-...
lectureforge subtitle 录课.mp4 --burn
```

产物在 `output/`：

```
lecture.ass              双语，烧录用
lecture.zh.srt           纯中文
lecture.bilingual.srt    中英双语
lecture.review.md        唯一需要人看的那些行
lecture.subtitled.mp4    成片
```

## 术语表不能省

不给术语表，中文准确率掉到 90% 左右，英文更糟——「梯度提升树」会被翻成 *gradient raised tree*，而且每一处都得改。

`terms.json` 是一次性投入、每节课复用：

```json
{
  "zh2en":  { "梯度提升树": "Gradient Boosting Decision Tree" },
  "fixups": { "你和上一": "拟合上一" },
  "review": ["残差"]
}
```

控制在 200 条以内效果最好，太长反而稀释 `initial_prompt` 的作用。样例见 [`examples/terms.example.json`](examples/terms.example.json)。

> 修正规则必须是**词组级**的。把单字「数」全局替换成「树」，会毁掉所有「数字」。

## 工作流程

```
录像 ──► ffmpeg ──► 16 kHz float32 ──► faster-whisper ──► 词 + 置信度
                                                              │
                                      ┌───────────────────────┘
                                      ▼
                          断句（标点回溯，绝不切开词）
                                      ▼
                  繁→简 → 术语修正 → 数字规范化
                                      ▼
                  ┌───────────────────┴───────────────────┐
                  ▼                                       ▼
        review.md（16% 的条目）                  ASS / SRT（双语）
                                                          ▼
                                                  libass 烧录
```

改代码前值得知道的几个决定：

- **音频用 ffmpeg 解码，不走 PyAV。** `faster-whisper` 1.2.x 调 `av.open(metadata_errors=...)`，该参数在 av 19 已移除。自己解码还顺手拿到波形，后面做能量分析要用。
- **简繁转换放在断句之后**，这样基于标点的断句规则看到的是原文。
- **数字串在断句之前先合并**——whisper 会把 `0.01` 拆成 `0.` + `01`，断错边界之后任何修正都救不回来。
- **置信度阈值取 0.45 而不是 0.55。** 词级置信度中位数是 0.993，用 0.55 会把 37% 其实正确的条目也标进复核清单，人就不想看了。

## 路线图

- [x] 词级转写 + 简繁统一
