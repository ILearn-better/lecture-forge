# 市面现成剪辑工作流调研

> **文档状态**：v0.1 设计底稿，成文于代码实现之前。
> 阶段 1（音频净化）、阶段 2（语音转写）、阶段 5（双语字幕）已落地；
> 阶段 3（卡壳判定）与阶段 4（剪辑渲染）仍是设计，未实现 —— 见 [README](../README.md) 的路线图。

> 调研时间：2026-10-26　｜　目标场景：45min 级中文录课，卡壳/噪声处理 + 中英双语字幕
> 本机实测环境：i5-12450H / 16G / ffmpeg 2026 GPL / auto-editor 29.3.1

---

## 一、结论先行

**有现成工作流，但没有一个能完整覆盖你的场景。缺的那块恰好是你最在意的：区分"卡壳"和"故意停顿"。**

原因很直接：

1. **所有工具的判定逻辑都是纯声学的**——"音量低于阈值 + 持续超过 X 秒 → 剪掉"。没有语义理解，不知道老师是不是在等学生思考。
2. **所有工具都为「短视频口播」优化**（15 秒~10 分钟），不是为 45 分钟课堂设计。长视频普遍卡顿甚至崩溃。
3. **"留白思考"是教学场景独有的需求**，短视频里不存在"等观众想三秒"这回事，所以通用产品不会有这个功能。

## 二、工具全景（按适配度排序）

| 工具 | 形态 | 卡壳/停顿判定方式 | 中文 | 双语字幕 | 45min 长视频 | 成本 |
|---|---|---|---|---|---|---|
| **剪映专业版** | 桌面/手机 | 智能剪口播：词表+静音，**标记后人工确认** | 优秀 | ✅ 内置翻译 20+ 语种 | 勉强（需分段） | 免费 / 部分会员 |
| **auto-editor** | 开源 CLI | 响度 / 运动 / 字幕正则，**纯阈值** | 与语言无关 | ❌ | ✅ | 免费（Unlicense） |

| **AixCut** | SaaS | 对话式（接了 LLM），主打长素材 | ✅ | 部分 | ✅ 官方称数小时 | 积分制 |

### 几个关键事实（已核实）

- **Descript 直接排除**。官方帮助中心写明：支持 26 种语言，**"全部使用拉丁字母"**，中文/日文/俄文"暂不支持"；连 Filler word detection 都是 English-only。实测中文识别率约 70%、断句混乱。在国内还有加载超时问题。
- **剪映是目前最实用的现成方案**。智能剪口播能自动识别停顿、语气词、重复并标记为无效，你只需逐条确认删除；双语字幕是内置一键功能。缺点是 45 分钟视频要人工确认上百个剪点，很累；专业术语翻译必错。
- **auto-editor 值得作为基础设施**。5.2k star、Unlicense 协议、单二进制、能导出 Premiere/达芬奇/FCP 的 XML 时间轴，可以当"智能预处理器"用。

## 三、本机实测：为什么现成工具解决不了"故意停顿"

我造了一段 23 秒的测试素材（正常讲解 + "嗯" + 长停顿 + 意图留白），用 auto-editor 29.3.1 实跑：

### 测试 A：纯音量阈值（默认思路）

```
auto-editor test.mp4 --edit audio:threshold=0.04 --preview
```
```
input:   0:00:23.00   100%
output:  0:00:14.00   60.87%
diff:   -0:00:09.00  -39.13%     ← 剪掉 39%
cuts:  3 个，平均 2.4s
```

**问题**：它把"大家想一想"之后那 4 秒留白也当静音剪掉了。这段恰恰是整节课最该保留的地方。

### 测试 B：字幕正则保护意图词

```
auto-editor test_sub.mp4 --edit "(or audio:threshold=0.04 subtitle:pattern=想一想)" --preview
```
```
diff: -0:00:09.00  -39.13%     ← 和测试 A 结果一模一样
```

**问题**：意图词保护**完全没生效**。原因很明确——字幕只覆盖"台词所在的时间段"，**覆盖不了台词之后的沉默**。而"大家想一想"之后的那 4 秒沉默，才是真正要保护的留白。

### 测试 C：字幕正则本身

```
auto-editor test_sub.mp4 --edit "subtitle:pattern=嗯" --preview
→ 只保留匹配行，23s 只剩 1s（语义是"保留"而非"剪掉"）
```
```
--when-active cut     → Error! 该参数已在 29.3.1 移除
```
且字幕必须先 `-c:s mov_text` 内嵌进 mp4，不能用外挂 srt。

### 实测结论

> **纯声学工具的"保护"能力，最多只能保护到"有台词的那一段"，无法保护"台词之后的沉默"。**
> 而教学留白恰恰全部发生在"台词之后的沉默"里。这是范式级的缺口，不是调参能解决的。

要解决它，判据必须能同时看到**台词文本 + 时间轴 + 文本前后各 8 字的上下文窗口**——也就是必须自己写判定逻辑。

## 四、三条可行路线

### 路线 A：剪映一站式（零开发，今天就能用）

```
录课 → 剪映「智能剪口播」确认剪点 → 智能字幕 → 双语翻译 → 导出
```

- **投入**：0 开发，半天上手
- **产出质量**：中文字幕好，双语字幕能用（术语需改），剪点需人工确认
- **适合**：先验证需求，或产量很低（每周 1~2 节）
- **天花板**：45min 课要确认上百个剪点；不能批量；判据无法定制

### 路线 B：开源工具链组合（半天部署）

```
ffmpeg 降噪/响度 → auto-editor 去静音 → AutoCut/剪映 出字幕 → Subtitle Edit 做双语
```

- **投入**：半天到一天
- **优点**：免费、可脚本化、可批量、auto-editor 能导出 XML 交给达芬奇精修
- **天花板**：判定仍是能量阈值，解决不了故意停顿
- **注意**：AutoCut 在 Python 3.12+ / moviepy 2.x 下有兼容性报错，需改源码

### 路线 C：自建语义流水线（上一版方案）

```
录制规范 → 降噪 → faster-whisper 词级转写 → 7 信号语义判定 → trim+concat 一次编码 → 双语 ASS
```

- **投入**：1~2 天开发 + 调参
- **唯一能做**：语义级卡壳判定、意图留白保护、板书画面保护、批量无人值守
- **成本**：一次性开发，之后每节课 1 小时机器时间 + 30 分钟人工复核

## 五、推荐：渐进式混合，不要一上来就自建

| 阶段 | 做什么 | 用什么 | 目的 |
|---|---|---|---|
| **第 1 步**（本周） | 先跑通一遍 | 剪映一站式 | 拿到一节成品课，确认"双语字幕"到底要多好、留白到底多重要 |
| **第 2 步**（下周） | 换掉剪辑环节 | auto-editor + 参数调优 | 验证批量能力，体会纯阈值剪法的具体翻车点 |
| **第 3 步**（按需） | 上语义判定 | 自建流水线，复用前两步的字幕与参数 | 只在第 2 步确实不够用时才做 |

**理由**：自建流水线的价值 100% 集中在"语义判定"这一个环节。如果你实际用下来发现——用剪映手动确认剪点也就多花 20 分钟，或者课堂本身很少有需要保护的留白——那自建就不值得，直接停在路线 A 或 B。

反过来，如果你每节课都要处理板书停顿、每节课都有"再讲一遍"的重复内容、每周要出 5 节以上，那么自建流水线的投入一周就能回本。

## 六、如果走路线 C，可以直接复用的现成件

不必从零写，这几块直接拿来用：

| 环节 | 现成件 | 说明 |
|---|---|---|
| 音频净化 | ffmpeg `afftdn` / `arnndn` / `loudnorm` | 本机已验证可用 |
| 转写 | `faster-whisper` medium int8 | CPU 唯一可行方案 |
| 剪点粗筛 | `auto-editor --export clip-sequence` | 先用它出候选剪点，再用语义模型二次过滤 |
| 字幕双语合并 | `Subtitle Edit`（开源）| 内置 DeepL 批量翻译 + 双语格式导出 |
| 渲染 | ffmpeg `trim`+`concat` 一次编码 | 前文方案已详述 |
