# 录课后期自动化工作流 · 技术方案

> **文档状态**：v0.1 设计底稿，成文于代码实现之前。
> 阶段 1（音频净化）、阶段 2（语音转写）、阶段 5（双语字幕）已落地；
> 阶段 3（卡壳判定）与阶段 4（剪辑渲染）仍是设计，未实现 —— 见 [README](../README.md) 的路线图。

> 目标：把「录制 → 净化 → 剪卡壳 → 双语字幕」从人工 2~4 小时压缩到无人值守 1 小时 + 人工复核 30 分钟。
>
> 硬件前提：i5-12450H / 16G / Intel 核显 / 无独显 → **全部走 CPU 推理与软件编码**，方案中的所有选型已按此约束校准。

## 一、总体架构

```
┌─────────────┐   ┌─────────────┐   ┌──────────────┐   ┌─────────────┐   ┌──────────────┐
│ 0. 录制规范  │──▶│ 1. 音频净化  │──▶│ 2. 语音转写   │──▶│ 3. 卡壳判定  │──▶│ 4. 剪辑渲染   │
│  (一次性)    │   │ 降噪/响度    │   │ 词级时间戳    │   │ 打分模型     │   │ 一次编码     │
└─────────────┘   └─────────────┘   └──────────────┘   └──────────────┘   └──────┬───────┘
                                                                                  │
                                          ┌───────────────────────────────────────┘
                                          ▼
                                   ┌──────────────┐   ┌──────────────┐
                                   │ 5. 字幕产出   │──▶│ 6. 烧录/交付  │
                                   │ 中文→术语→英译│   │ 硬字幕 or 外挂│
                                   └──────────────┘   └──────────────┘
```

**关键设计原则（决定成败的三条）**

| 原则 | 说明 | 不这么做会怎样 |
|---|---|---|
| **压缩而非删除** | 2.4s 的卡壳压到 0.35s，不归零 | 全删干净 → 像机关枪，听 3 分钟就累 |
| **切点落在静音中点** | 每个切割点两侧各留 ≥80ms 静音余量 | 切在词边界 → 吃掉半个字，最典型的翻车 |
| **剪辑后必须重映射字幕时间轴** | 用 EDL 做时间映射 | 不映射 → 字幕整片错位，越到后面错越多 |

## 二、阶段 0：录制规范（上游决定下游上限）

这一步不做，后面全靠算法硬救，救不回来。

| 项 | 建议 | 原因 |
|---|---|---|
| 采样率 | 48kHz / 24bit | 后期降噪与重采样留足余量 |
| 麦克风距离 | 15~20cm，加防喷罩 | 距离决定信噪比，软件救不了近场缺失 |
| **必录 10 秒房间静音** | 开录前静坐 10s 不发声 | 给降噪器一个**精确的噪声指纹**，降噪质量提升非常明显 |
| 录制容器 | MKV（崩溃可修复）或 MP4 | MKV 断电不丢文件 |
| 音轨 | 麦克风独立一轨，系统声独立一轨 | 后期只处理麦克风轨，系统声单独混入 |
| **录制时不要开降噪** | 任何软件降噪都关掉 | 原始素材不可逆，降噪放到后期做 |
| 摄像头画面 | 与屏幕录制分离轨 | 排版可后期决定（画中画/全屏/切镜） |

> 一个实用技巧：录制时**手动打点**。遇到要保留的"故意留白"（比如让学生做题的 30 秒），对着镜头说一句「**标记·保留**」。判定模型会把这个词当强保护信号，后面全部自动跳过。这比事后回听靠谱得多。

## 三、阶段 1：音频净化

```
麦克风轨 → highpass(80Hz) → afftdn(自适应噪声底) → [可选 arnndn] → loudnorm(两遍) → 16k 单声道
```

| 步骤 | 工具 | 参数 | 说明 |
|---|---|---|---|
| 去低频 | `highpass=f=80` | — | 空调、桌子震动、脚步 |
| 频域降噪 | `afftdn` | `nr=12, nf=-32` | 稳态噪声（风扇/空调）；`nr>20` 会出现"水声"伪影 |
| RNN 降噪（可选） | `arnndn` | `sh.rnnn` 模型 | 对非稳态噪声（键盘、纸张）更好，比 afftdn 自然 |
| 齿音抑制 | `deesser` | 按需 | 只在"嘶/次"刺耳时开 |
| 响度标准化 | `loudnorm` | `I=-16, TP=-1.5, LRA=11` | EBU R128，视频平台通用标准 |
| 重采样 | `aresample=16000` | — | 给 ASR 用，降低推理量 |

**噪声底自动估计**：若没有录 10 秒静音，取全片能量最低的 1% 分位作为噪声底，反推 `nf` 参数。比手填可靠。

**为什么 loudnorm 要两遍**：第一遍测量得到真实的 I/TP/LRA，第二遍用测量值做线性（非动态）压缩。单遍动态模式会压扁讲课的抑扬顿挫。

## 四、阶段 2：语音转写

**选型：faster-whisper + CTranslate2**

| 项 | 值 | 理由 |
|---|---|---|
| 模型 | `medium` int8 | `small` 中文错误率明显偏高；`large-v3` 在 CPU 上约 0.3x 实时（45min 要 2.5h），不可用 |
| 精度 | `int8` | CPU 上最快，质量损失可忽略（<1%） |
| 线程 | `cpu_threads=8` | i5-12450H 是 8 核 12 线程，给 8 线程留出 IO 余量 |
| VAD | 开启 | 跳过静音段，讲课视频通常有 20~30% 静音，提速 1.3~1.5 倍 |
| beam_size | 2 | 5 会慢 2 倍，1 会掉准确率 |
| 词级时间戳 | **必须开启** | 整个卡壳判定的基础数据 |

**准确率提升的关键 —— 术语注入**

`initial_prompt` 塞入课程术语表，让模型进入对应领域的语言模型分布。这是投入产出比最高的一步：

```python
initial_prompt = "本节课涉及术语：随机森林、梯度提升树、特征重要性、交叉验证、过拟合、正则化、超参数搜索。"
```

实测可将专业术语识别率从 70~85% 提升到 90~95%。术语表直接从你的讲义/PPT 里抽，200 字以内效果最好。

## 五、阶段 3：卡壳判定模型（核心）

### 5.1 先想清楚：人是怎么区分的

人听课时判断"这是卡壳"还是"这是故意停顿"，其实只用了三条线索：

1. **声音线索** —— 有没有"嗯……呃……"的拖音？语速是不是突然垮下来了？
2. **语法线索** —— 这句话说完了吗？"我们来看一下这个……"停顿，明显没说完；"好，我们进入下一部分。"停顿，这是段落结束。
3. **教学语境** —— 老师是不是在等学生反应、留白思考、或者正在转身写板书？

机器就把这三条量化成 7 个信号打分。

### 5.2 七个判定信号

| # | 信号 | 提取方式 | 指向 | 权重 |
|---|---|---|---|---|
| S1 | **停顿时长**（相对全片分布） | 词级时间戳的词间 gap，用 P50/P95 做自适应归一化 | 越长越可疑 | 0.30 |
| S2 | **填充音 / 犹豫标记** | 停顿前末尾 2 词、停顿后开头 1 词是否命中填充词表 | 强卡壳 | 0.30 |
| S3 | **句法未完成** | 停顿前最后一个字/词是否落在「虚词集」 | 强卡壳 | 0.20 |
| S4 | **重启重复** | 停顿后开头 2~4 字与停顿前末尾 2~4 字的重叠度 | 强卡壳 | 0.25 |
| S5 | **语速骤降** | 停顿前 3 秒的字符/秒，与全片均值比 | 弱卡壳 | 0.10 |
| S6 | **教学意图词**（保护） | 前 8 字/后 8 字内命中意图词表 | **故意停顿 → 强制保留** | −∞ |
| S7 | **画面活跃度**（保护） | 停顿区间内的平均帧差 vs 全片均值 | 板书/翻页 → 保留 | −0.40 |

### 5.3 词表设计（这是模型的"常识"）

**硬填充词（判定权重 1.0）** —— 独立出现几乎必然是卡壳
```
嗯 呃 额 唔 诶 嘶 唉     （另含拖长音的 啊——、哦——）
```

**软填充词（权重 0.5）** —— 高频但正常口语也常见
```
那个 这个 就是说 怎么讲 反正 然后 那么 所以说
```
> 注意：`那个/这个` 只在**紧邻停顿时**才算信号；连说两遍（"那个那个"）权重升到 0.9。

**强未完成虚词（权重 0.8）** —— 这些字结尾在语法上不可能成句
```
的 了 是 在 和 把 被 因为 如果 虽然 但是 而且 由于 无论 不管 除了 要是 假如
```
**弱未完成虚词（权重 0.4）** —— 可能成句，但在讲课语境中多为未完
```
然后 这个 那个 就是 所以 那么 接着 而 且 但 就 也 都 很 给 对 从 到 为
```

**教学意图保护词（一票否决）**
```
想一想 想一下 想想 思考 你们想 大家想 算一下 看一下 试试 试着 自己动手
有没有问题 对不对 是吧 暂停 数三下 留白 回忆一下 复习一下 标记·保留
```
> 出现在停顿前 8 字或后 8 字内 → **无条件保留**。剪掉这些等于毁课。

### 5.4 打分与决策

```python
score = 0.30*S1 + 0.30*S2 + 0.20*S3 + 0.25*S4 + 0.10*S5 + S7_bonus
# 各信号归一化到 [0,1]，score 再 clip 到 [0,1]

if S6 命中:                          verdict = "intentional"   # 保留原长度
elif score >= 0.60:                  verdict = "hesitation"    # 压缩到 0.35s
elif 0.35 <= score < 0.60:           verdict = "compress"      # 压缩到 0.55s
elif gap < 0.45s:                    verdict = "breath"        # 自然气口，不动
else:                                verdict = "keep"
```

**叠加两条硬规则**

| 情况 | 处理 |
|---|---|
| `gap > 6s` 且无意图词、画面静止 | 强制压到 2.0s（走神/离开） |
| `gap > 1.2s` 且画面活跃度高 | 强制保留（板书/演示，剪了画面会跳） |
| 孤立填充词（"嗯"单独成词且 <0.8s） | 直接删词，前后 gap 合并后重新判定 |

### 5.5 三个必须做的工程细节

**① 静音边界精修（防"吃掉半个字"）**

whisper 的词级时间戳在长静音处会偏。必须用能量包络二次校正：找到 gap 内能量真正跌到噪声底的位置，作为真实语音结束点。

**② 切点居中（防"跳帧感"）**

不切在词边界，而是：
```
cut_start = gap_start + keep_dur/2
cut_end   = gap_end   - keep_dur/2
```
切点永远落在静音中点，离两侧语音都最远，是听觉上最不突兀的位置。

**③ 最小保留 0.18s**

`keep_dur < 0.18s` 时强制提到 0.18s。低于这个值，切点会逼近语音，出现"咔"的爆音和气息截断。

## 六、阶段 4：剪辑渲染

**方案：`trim` + `concat` filter，一次编码**

```
[0:v]trim=s1:e1,setpts=PTS-STARTPTS[v0]; [0:a]atrim=s1:e1,asetpts=PTS-STARTPTS[a0];
[0:v]trim=s2:e2,setpts=PTS-STARTPTS[v1]; [0:a]atrim=s2:e2,asetpts=PTS-STARTPTS[a1];
... (N 段)
[v0][a0][v1][a1]...[vN][aN]concat=n=N:v=1:a=1[v][a]
```

**为什么不用其他方案**

| 方案 | 问题 |
|---|---|
| `-c copy` 分段切 | 切割点被吸附到关键帧，误差可达数百 ms → 音画不同步 |
| 分段重编码 + concat demuxer | 每段有 ~20ms 音频对齐误差，切 40 处累积成明显漂移 |
| `select`/`aselect` 表达式 | 视频按帧、音频按采样，两套时钟各自漂移 |
| **`trim`+`concat` 一次编码** ✅ | 音视频同一时间基准做 trim，严格同步；一次编码无二次损失 |

filter 表达式用 `-filter_complex_script` 文件传入，避开 Windows 命令行长度限制。

**编码参数（CPU 优化）**
```
-c:v libx264 -preset veryfast -crf 20 -pix_fmt yuv420p
-c:a aac -b:a 192k -ar 48000
```
`veryfast` 在 i5-12450H 上约 1.5~2.5x 实时。`crf 20` 对 PPT/讲台画面几乎无损（这类画面本身冗余度高）。

**可选：字幕与剪辑合并到一次编码** —— 把 `subtitles=` 滤镜接到 concat 输出上，省掉一遍 20 分钟的重编码。

## 七、阶段 5：双语字幕

### 7.1 时间轴重映射（最容易漏的一步）

剪辑后视频时长变了，所有字幕时间戳必须通过 EDL 映射：

```python
def remap(t):
    acc = 0.0
    for (s, e) in keep_intervals:
        if t >= e:      acc += e - s
        elif t > s:     return acc + (t - s)
        else:           return acc
    return acc
```
- 整条字幕落在被删区间 → 丢弃
- 跨切割点 → 起点贴到边界，自动变短

### 7.2 中文 → 英文

| 步骤 | 做法 |
|---|---|
| 1. 断句 | 按标点 + 最大 18 字/条、最长 6s 切分 |
| 2. 术语统一 | 用术语表强制替换（"梯度提升树" → "Gradient Boosting Tree"，不允许模型自由发挥） |
| 3. 翻译 | LLM 逐条翻译，注入上一条作为上下文（保持术语与语气连贯） |
| 4. 长度约束 | 英文超 2 行则回译压缩，避免字幕挡画面 |

### 7.3 输出格式

双语 ASS，中文在上、英文在下：

```
Style: Bilingual,Microsoft YaHei,56,...   ; 中文
{\fs56}我们来看一下梯度提升树的原理\N{\fs38\1c&HD0D0D0&}Let's look at how gradient boosting trees work.
```

中文用 `Microsoft YaHei`（系统自带，无需装字体），英文可用 `Segoe UI`。描边 2.5px + 半透明阴影，保证任何画面背景下可读。

## 八、预期效果

### 8.1 量化指标

| 指标 | 预期值 | 说明 |
|---|---|---|

| 明显卡壳检出率 | **92~96%** | "嗯——那个——"这类 |
| 长静音检出率 | **99%** | 能量检测本身就很准 |
| **误剪率** | **1~3%** | 主要出现在边界模糊的思考停顿 |
| **漏检率** | **5~10%** | 主要是 0.5~0.7s 的短犹豫 |
| ASR 字准确率 | **92~96%** | 普通话清晰讲课，medium int8 |
| 术语识别率 | **90~95%** | 加术语表后的值；不加约 70~85% |

| 英文字幕可用度 | **85~90%** | 机翻+术语表，教学表达需人工润色 |

### 8.2 耗时对比（45min / 1080p / i5-12450H）

| 环节 | 无人值守耗时 |
|---|---|
| 音频净化 | 1~2 min |
| 语音转写（medium int8 + VAD） | 25~40 min |
| 卡壳判定 + 生成 EDL | < 10 s |
| 视频剪辑重编码 | 12~25 min |
| 字幕翻译 | 2~5 min |
| 字幕烧录 | 10~20 min（合并到剪辑则省去） |
| **合计** | **约 50~85 min（可挂着干别的）** |

| 方式 | 总人工时间 |
|---|---|
| 传统手工剪辑 + 打轴字幕 | 2~4 小时 |
| **本流程** | 无人值守 1 小时 + **人工复核 20~40 分钟** |

**效率提升约 4~6 倍**，且质量更稳定（人剪到第 40 分钟会疲，机器不会）。

### 8.3 人工复核清单（只需做这 4 件事）

1. 看一遍成品，标记"这里不该剪"的位置（回填到保护白名单）
2. 扫字幕，改专有名词错字（从 95% 拉到 99%）
3. 抽查英文字幕的教学表达
4. 确认片头片尾、音量

## 九、方案的边界（做不到什么）

诚实说明，避免预期落空：

| 局限 | 原因 | 缓解 |
|---|---|---|
| 板书/演示段的停顿判不准 | 算法无法理解"此时老师在画画" | 画面活跃度保护 + 口播"标记·保留" |
| 说错词不会自动纠正 | 只处理停顿与填充音 | 需另加「重说检测」，成本高，暂不做 |
| 多人连麦无法分离说话人 | 未接 diarization | 后续可加 pyannote |
| 英文字幕非母语级 | 机翻+术语表 | 人工润色或换专业译后编辑 |
| CPU 转写慢 | 无独显 | 可换云端 ASR（如 Paraformer）或加显卡，速度提升 5~10 倍 |
| 极安静的房间也会被降噪 | `afftdn` 会削掉气声细节 | 安静环境把 `nr` 降到 8，或直接关降噪 |

## 十、需要你确认的 4 个点

这些会实际改变流程结构，定了我就直接落地成可跑的代码：

1. **录制方式** —— OBS 本地录？还是腾讯会议/Zoom 录？有没有麦克风+系统声双音轨？
2. **字幕语言策略** —— 中文课配英文字幕？还是本来就要中英双语授课（那英文是原声还是后配）？
3. **画面形态** —— 纯屏幕共享？还是真人出镜画中画？（影响画面活跃度保护阈值）
4. **交付平台** —— B站/慕课/自有站点？（决定分辨率、响度、字幕是硬压还是外挂）
